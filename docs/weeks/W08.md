# W08 · HoleFeature 연계 · 검색 반경 · 배타 매칭

## 목표
수집한 홀 묶음(HoleCluster)에 탭 정보를 붙이고(HoleFeature 연계), 묶음 쌍을 검색 반경 Cap 으로 걸러 그리디 배타 매칭으로 짝을 확정한다.
판정은 거리뿐이다: Tol 이하 = OK · Tol 초과 Cap 이하 = 위치 불일치 NG · Cap 초과 = 후보 아님(줄 없음).
지름 정합 · 탭/클리어런스 규격 판정은 12주차. 이번 주 탭 정보는 "읽어서 보여주기"까지.

## 진행 순서 (한 단계에 한 군데만 바꾼다)
- 8-1 Interop 이름 확인 · api_paths.md 행 추가 (실행 없음)
- 8-2 데이터 모델 확장 · 호출 없음 · 컴파일만
- 8-3 연계 1차 (옆벽 → CreatedByFeature → 시드 역추적) · 진단 txt 만 · 태그 w08-link1-done
- 8-4 연계 2차 (파트의 HoleFeature 순회 · 중심 거리 0.02 mm) + Tapped · ThreadDesignation · 진단 txt 만 · 태그 w08-link-done
- 8-5 Cap/Tol 그리디 배타 매칭 · 진단 txt 만 (폼은 값 전달 한 줄만) · 태그 w08-match-done
- 8-6 폼 연결 · 결과 그리드 8열 · 더블클릭 줌 재연결
- 8-7 검증 · 홀간 거리 확인-1 · M7 · nested_top · Cap 2.0 / 300 비교
- 8-8 마감 · 태그 w08-done

## 시작 전 합의
- 연계 정보는 숫자·문자열만 HoleCluster 에 담는다 (W05 결정). COM 객체는 수집 함수 안에서만 쓰고 보관하지 않는다
- W06 피처 추적 함수(FindHoleAncestor · GetParentFeatures)는 수정하지 않는다. 시드 역추적은 축약판을 새 함수로 추가한다 (부모 피처 첫 항목만 따라 올라감 · 깊이 상한 intMaxFeatureDepth 재사용)
- 배타 사용 집합은 v4 문구대로 A쪽 · B쪽 분리 (A = 리프 번호가 작은 쪽). 하나의 공유 집합 방식과 Cap 300 에서 결과가 다르므로 예측 표에 둘 다 적는다
- 정렬은 거리 오름차순 하나만 쓴다 (동률 처리 3키는 14주차)
- 폼의 공차 입력 2개를 Cap(후보 범위) · Tol(정렬 공차)로 이어받는다. 시작값 2.0 / 0.1 · 입력 검증(0 이하 · Tol ≥ Cap 이면 실행 안 함) 유지 · NumericUpDown 최대값이 300 미만이면 300 이상으로 올린다
- Cap 최종값(10 mm)은 10주차에서 확정. 이번 주는 2.0 으로 돌리고, 비교용으로 300 도 돌린다
- 그리드 8열 = No. | 판정 | 부품 A | 부품 B | 거리(mm) | 타입 | 탭 A | 탭 B. "타입" 열 = 연계 단계 표기 (예: 1/1 · 1/2 · 1/없음). 부품명 열이 길어 화면을 넘치면 고치지 않고 기록 (결정 보류)
- 더블클릭 줌은 기존 Zoom.MoveCameraToTarget 을 그대로 다시 연결한다. 목표점 = 두 묶음 중심의 중점. 엉뚱한 곳으로 가면 고치지 않고 기록 (10주차)
- Option Strict On · 헝가리안 · 축약 금지 · 파일 분리 단위 W07 그대로

## A
- 연계 1차: 묶음의 첫 채택 루프 → 루프의 edge → Edge.Faces 중 평면 face 가 아닌 면(옆벽) → Face.CreatedByFeature → 시드 역추적 → HoleFeature
- 연계 2차: 1차 실패 시에만 · 그 리프 파트의 HoleFeature 전체를 순회해 HoleCenterPoints 와 묶음 중심 거리 0.02 mm 이내로 매칭. 파트 좌표 ↔ 조립품 좌표 변환은 리프 Transformation 을 한 번만 적용 (W04 결정 확인용으로 nested_top 에서 검증)
- 연계 성공 시 Tapped · ThreadDesignation 읽기 (탭은 FastenerSize · HoleDiameter 가 E_FAIL 이므로 읽지 않는다 · TapInfo 는 HoleTapInfo 로 TypeOf 확인 후 변환)
- 그리디 배타 매칭: 서로 다른 리프 묶음 쌍 → Cap 이내 후보 → 거리 오름차순 → 확정 시 A쪽 · B쪽 사용 집합에 기록 → 재사용 금지
- 진단 txt: 연계 1차 · 2차 · 실패 개수와 실패 목록(리프 · 묶음 번호 · 사유) · 매칭 요약과 줄 목록

## B
- Cap · Tol 이어받기 · 입력값을 RunLoopCollection 으로 전달
- 결과 그리드 8열 · 상태 라벨 요약 한 줄 (확정 N · OK N · NG N · 연계 실패 N)
- MatchPair 중점 좌표 → 더블클릭 줌 재연결
